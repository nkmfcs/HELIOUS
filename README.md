# HELIOUS

Склад и касса детских чешек. Цвета: белые, чёрные, серые, золотые. Размеры 14–28, учёт по 5 пар.

Живое приложение: [helious.up.railway.app](https://helious.up.railway.app)

## Возможности

- Склад: коробки #1–#5, приход, остатки по цвету и размеру, низкие остатки.
- Клиенты и заказы ведутся отдельно; заказ можно вставить текстом (парсер распознаёт цвета и размеры).
- Касса, долги клиентов, работники и их начисления.
- Предзаказ, если на складе меньше 30 пар, и производственный конвейер: партии проходят этапы крой → швейки → упаковка → готово с привязкой работников.
- Отчёты по дням и месяцам.
- Облако: автосохранение и проверка изменений каждые 30 секунд в открытой вкладке, при возврате в приложение и при восстановлении сети. Ручной выбор нужен только при независимых изменениях обеих версий или неизвестной истории непустой локальной копии.

## Стек

TanStack Start (React 19, TanStack Router) · Vite · Tailwind CSS 4 · Zustand · Better Auth · Postgres (Neon) / PGLite для локальной разработки · Nitro (деплой на Railway).

## Быстрый старт

Нужен Node.js 22.12 или новее.

```bash
npm install
npm run dev        # http://localhost:8080
```

Без `DATABASE_URL` приложение использует встроенную базу PGLite (Postgres в WASM) — ничего настраивать не нужно.

## Переменные окружения

Шаблон — `.env.example`. Реальный `.env` в репозиторий не коммитить.

| Переменная                                                   | Назначение                                      |
| ------------------------------------------------------------ | ----------------------------------------------- |
| `DATABASE_URL`                                               | Строка подключения к Neon. Пусто — PGLite       |
| `BETTER_AUTH_URL`                                            | Публичный адрес сервиса на Railway              |
| `BETTER_AUTH_SECRET`                                         | Секрет, 32+ байта, только в окружении           |
| `VITE_AUTH_ENABLED`                                          | `false` отключает авторизацию (только локально) |
| `AUTH_EMAIL_PASSWORD_ENABLED`, `VITE_EMAIL_PASSWORD_ENABLED` | Вход по email и паролю (сервер / клиент)        |

`VITE_*` читаются на этапе сборки: после их изменения нужен новый деплой.

## Структура проекта

```
src/

    _app/            Страницы за авторизацией: склад, заказы, клиенты, касса, работники, отчёты
    login.tsx        Вход и регистрация (email + пароль)
    api/auth/$.ts    Эндпоинты Better Auth
  components/        Компоненты приложения; ui/ — базовые (button, card, input, badge)
  lib/
    types.ts         Доменные типы и константы (SIZES, COLORS, PACK, SELL_PRICE)
    store.ts         Единое состояние склада (Zustand) и все действия над ним
    inventory.ts     Чистая логика остатков: нормализация, списание, возврат
    boxes.ts         Раскладка размеров по коробкам #1–#5
    production.ts    Производственные партии: этапы, остатки «в производстве»
    stats.ts         Отчёты, долги, остатки кассы
    format.ts        Форматирование чисел, дат, названий цветов
    order-parser.ts  Разбор текстового заказа
    sync.ts          Облачная синхронизация и разрешение конфликтов
    warehouse.functions.ts  Серверные функции загрузки/сохранения снимка
    db.ts            Выбор базы: Neon или PGLite
    auth/            Авторизация (Better Auth, middleware, гейты)
    multiplayer/     P2P-комнаты (WebRTC)
migrations/          SQL-миграции (применяются scripts/migrate.mjs)
scripts/             Запуск миграций и тесты
public/              Иконки и PWA-манифест (установка на домашний экран)
```

## Как устроены данные

- Всё состояние склада — один снимок `WarehouseState` (см. `src/lib/types.ts`). Он хранится локально (localStorage через Zustand) и в облаке (таблица `warehouse_snapshot`).
- Каждое сохранение в облаке увеличивает `revision`. Если ревизия на сервере ушла вперёд, запись отклоняется — так одно устройство не затирает изменения другого.
- Изменения остатков проходят через `inventory.ts`: количество всегда целое и не меньше нуля.

## Деплой

Railway + Neon. Настройки сборки — в `railway.json` (`npm run build`, запуск `npm start`). Переменные окружения из `.env.example` задаются в Railway; `DATABASE_URL` — pooled-строка Neon. Миграции применяются автоматически в конце сборки.

Cookie сессии называются `__Host-grok-auth.*` — имена остались от прежней версии, чтобы пользователям не пришлось входить заново. Переименовывать их не нужно.
